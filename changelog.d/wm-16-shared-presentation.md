- **One set of presentation helpers for web and mobile**: `KIND_LABEL`, `waitedLabel` and `linkHost` now live once, in a new workspace package `packages/ui` (`@watchman/ui`, the shared presentation layer), and both apps import them; each app's own copy is gone, and a lint rule refuses a new one under those names. (The single-file artifact `artifacts/watchman-v0.tsx` cannot import a workspace package and keeps its own labels, on purpose.) `linkHost` had drifted (the web copy used `new URL(...).hostname`, which throws on bad input; the mobile copy used a regular expression, which returned `user@host` for a link with a user part). It now has one behaviour on both apps: it never throws, it never shows a user part (the host is what follows the last `@`, as a browser reads it), and it answers lower-case with no port. It answers only for a link spelled exactly `https://`, an optional user part, an ASCII host name and an optional port; for any other spelling, including ones a browser would repair (a stray space, a missing slash, a non-ASCII host), it answers with an empty string instead of guessing. A new `linkDestination` prints that host, or "another site" when it cannot be read, so no screen says "opens" with nothing after it. One table of 60 links pins the behaviour in the package and in each app's tests.
