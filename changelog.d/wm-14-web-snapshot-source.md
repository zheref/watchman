- **One source rule for the web app and the MCP server**: the web loader (`apps/web/src/server/snapshot.ts`) now resolves its snapshot through `packages/core`'s `resolveSnapshotSource`, with Node's file system and the synthetic fixture injected, the same call the MCP server makes. It keeps no copy of the decision tree or of `unavailableSnapshot` and adds only the time of the read, so a change to the rule in core reaches the dashboard and the agents together. What the dashboard shows is unchanged: the labelled fixture when `WATCHMAN_SNAPSHOT_DIR` is unset, the newest usable file when it is set, and every tile "no data" with a path-free reason when the directory cannot be read. A test holds how the loader feeds core's rule: its answer must equal core's for the same reader and fixture, plus the time of the read (zheref/watchman#14).
